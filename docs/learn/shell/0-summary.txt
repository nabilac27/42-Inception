# Docker Compose Environment Variables

## 1. What Are Environment Variables?

Environment variables are `KEY=value` settings that programs use to configure their behavior.

Example:

```dotenv
MARIADB_DATABASE=wordpress
MARIADB_USER=wp_user
```

| Variable           | Value       | Purpose                    |
|--------------------|-------------|----------------------------|
| `MARIADB_DATABASE` | `wordpress` | WordPress database name    |
| `MARIADB_USER`     | `wp_user`   | Database application user  |

**Key concept:** Environment variables separate configuration from application code.

## 2. What Is a `.env` File?

A `.env` file is a text file containing environment variable definitions.

Example: `srcs/.env`

```dotenv
MARIADB_DATABASE=wordpress
MARIADB_USER=wp_user
DOMAIN_NAME=nchairun.42.fr
WP_TITLE=INCEPTION
```

Instead of hardcoding configuration in scripts, values are defined in one place.

**Key concept:** `.env` stores configuration values, but does not create databases or users by itself.

## 3. What Does `env_file` Do?

In `srcs/docker-compose.yml`:

```yaml
services:
  mariadb:
    env_file:
      - .env
```

`env_file` tells Docker Compose to load variables from the specified file into the container's environment.

```text
srcs/.env
    |
    | MARIADB_DATABASE=wordpress
    | MARIADB_USER=wp_user
    v
docker-compose.yml
    |
    | env_file:
    |   - .env
    v
MariaDB Container
    |
    +-- MARIADB_DATABASE=wordpress
    |
    +-- MARIADB_USER=wp_user
```

**Key concept:** `env_file` passes configuration values into a container.

## 4. Complete Configuration Flow

```text
srcs/.env
    |
    | Defines variables
    v
docker-compose.yml
    |
    | env_file loads variables
    v
MariaDB Container
    |
    | Environment variables available
    v
tools/init.sh
    |
    | Reads $MARIADB_DATABASE
    | Reads $MARIADB_USER
    v
MariaDB Server
    |
    +-- Creates database: wordpress
    |
    +-- Creates user: wp_user
    |
    +-- Grants permissions
```

**Key concept:** `.env` defines the configuration; `init.sh` uses it to initialize MariaDB.

## 5. How Does `init.sh` Access Variables?

Inside the container:

```bash
echo "$MARIADB_DATABASE"
echo "$MARIADB_USER"
```

Expected output:

```text
wordpress
wp_user
```

In a shell script:

```bash
DB_NAME="$MARIADB_DATABASE"
DB_USER="$MARIADB_USER"
```

- `$VARIABLE` expands to the variable's value.
- Double quotes preserve the expanded value as one shell argument.
- The variables are inherited from the container environment.

Example:

```bash
echo "$MARIADB_DATABASE"
```

Result:

```text
wordpress
```

**Important:** The shell expands variables. MariaDB SQL does not automatically expand shell variables.

For database creation, the initialization script must pass the configured values into SQL safely.

## 6. `.env` vs `env_file` vs `environment`

| Concept       | Purpose                                         |
|---------------|-------------------------------------------------|
| `.env`        | Stores variable definitions                     |
| `env_file`    | Injects variables from a file into a container  |
| `environment` | Defines container environment variables directly|
| `$VARIABLE`   | Accesses a variable in a shell script           |
| `${VARIABLE}` | Supports variable interpolation in Compose      |

Example using `env_file`:

```yaml
services:
  mariadb:
    env_file:
      - .env
```

Example using `environment`:

```yaml
services:
  mariadb:
    environment:
      MARIADB_DATABASE: wordpress
      MARIADB_USER: wp_user
```

Example using Compose interpolation:

```yaml
services:
  mariadb:
    environment:
      MARIADB_DATABASE: ${MARIADB_DATABASE}
      MARIADB_USER: ${MARIADB_USER}
```

**Important distinction:**

- `env_file` supplies variables to the container.
- `${VARIABLE}` substitutes values when Compose processes its YAML configuration.
- The Compose project `.env` file is commonly used for interpolation, but does not automatically inject every variable into containers.

## 7. Environment Variables vs Docker Secrets

| Environment Variables           | Docker Secrets                         |
|---------------------------------|----------------------------------------|
| General application settings    | Sensitive credentials                  |
| Available in process environment| Mounted as files                       |
| Accessed using `$VARIABLE`      | Read from `/run/secrets/`              |
| Example: database name          | Example: database password             |

Environment variables:

```dotenv
MARIADB_DATABASE=wordpress
MARIADB_USER=wp_user
```

Docker secret:

```bash
DB_PASSWORD=$(cat /run/secrets/db_password)
```

**Key concept:** Use environment variables for ordinary configuration and Docker secrets for sensitive passwords.

## 8. Inspect Environment Variables

Run on the host:

```bash
# Display environment variables inside MariaDB
docker exec mariadb env

# Display a specific variable
docker exec mariadb printenv MARIADB_DATABASE

# Display the database username
docker exec mariadb printenv MARIADB_USER

# Inspect the effective Compose configuration
docker compose -f srcs/docker-compose.yml config
```

Be careful: `env` and `docker compose config` can reveal sensitive values if passwords are stored as environment variables.

### Understanding `docker exec`

```bash
docker exec mariadb env
```

| Part          | Meaning                                |
|---------------|----------------------------------------|
| `docker exec` | Execute a command in a running container|
| `mariadb`     | Container name                         |
| `env`         | Print environment variables            |

General syntax:

```bash
docker exec <container> <command>
```

## 9. Common Linux Environment Variables

| Variable           | Purpose                                |
|--------------------|----------------------------------------|
| `PATH`             | Directories searched for executables   |
| `HOSTNAME`         | Container hostname                     |
| `HOME`             | User's home directory                  |
| `MARIADB_DATABASE` | WordPress database name                |
| `MARIADB_USER`     | Database application username          |

Example:

```text
PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin
HOSTNAME=015b6cacd74f
HOME=/nonexistent
MARIADB_DATABASE=wordpress
MARIADB_USER=wp_user
```

`HOME=/nonexistent` can be normal for a system account such as `mysql`, which does not require a regular interactive home directory.

## 10. Why Use Environment Variables?

Without environment variables:

```text
Database name hardcoded in scripts
           |
           v
Changing configuration requires code changes
```

With environment variables:

```text
.env
 |
 | MARIADB_DATABASE=my_blog
 v
Docker Compose
 |
 v
Container environment
 |
 v
Initialization script
```

Advantages:

- Separates configuration from code.
- Makes containers reusable.
- Simplifies development and deployment.
- Reduces duplicated configuration.
- Allows different settings for different environments.

**Important:** Changing the database name in `.env` does not automatically rename an existing database in a persistent MariaDB volume.

## 11. Inception Evaluation Questions

**Q: What is an environment variable?**

A key-value setting used to configure programs and processes.

**Q: What is a `.env` file?**

A text file containing environment variable definitions.

**Q: What does `env_file: .env` do?**

It tells Docker Compose to load variables from `.env` into the container's environment.

**Q: Does `.env` create the WordPress database?**

No. It only defines configuration values. The MariaDB initialization script creates the database.

**Q: How does `init.sh` access variables?**

Through shell expansion, such as `$MARIADB_DATABASE`.

**Q: What is the difference between `.env` and Docker secrets?**

`.env` stores ordinary configuration, while Docker secrets provide sensitive information through mounted files.

**Q: What is the difference between `env_file` and `environment`?**

`env_file` loads variables from a file; `environment` defines or overrides variables directly in Compose.

**Q: Why separate configuration from code?**

To reuse the same scripts and images with different configuration values.

**Q: Does changing `.env` update an existing database automatically?**

No. Existing database state persists independently and may require explicit database changes.

## 12. Quick Summary

- Environment variable = `KEY=value` configuration
- `.env` = File containing variable definitions
- `env_file` = Pass file variables into a container
- `environment` = Define container variables in Compose
- `${VARIABLE}` = Compose variable interpolation
- `$VARIABLE` = Shell variable expansion
- `docker exec` = Run commands inside a container
- `env` = Display environment variables
- `printenv` = Display environment variable values
- Docker secrets = Sensitive configuration stored as files
- `init.sh` = Uses configuration to initialize services

**One-sentence summary:**

The `.env` file defines configuration values, Docker Compose passes them into containers using `env_file`, and initialization scripts read those variables to configure services such as MariaDB.
