# Adminer

## 1. What is Adminer?

Adminer is a lightweight, web-based database management tool used to inspect and manage MariaDB through a browser.

In Inception, Adminer runs in a separate Docker container with Apache, PHP, and the `mysqli` extension.

| Component       | Purpose                                      |
|-----------------|----------------------------------------------|
| Adminer         | Web-based database administration            |
| Apache          | Serves the Adminer PHP application           |
| PHP             | Executes Adminer's application code          |
| `mysqli`        | Enables PHP to connect to MariaDB            |
| MariaDB         | Stores WordPress database records            |
| NGINX           | Provides HTTPS access through reverse proxy  |

**Key concept:** MariaDB stores the data; Adminer provides a graphical interface to manage it.

## 2. Architecture

```text
Browser
   |
   | HTTPS :8443
   v
NGINX
   |
   | Reverse proxy
   v
Adminer (Apache + PHP)
   |
   | TCP :3306
   v
MariaDB
   |
   v
WordPress Database
```

- NGINX receives HTTPS requests.
- Apache serves Adminer.
- PHP executes Adminer's code.
- `mysqli` connects PHP to MariaDB.
- MariaDB processes SQL queries.
- Adminer and MariaDB communicate through the Docker network.

## 3. Docker Configuration

### Dockerfile

Adminer uses Debian Bookworm as its base image.

```dockerfile
FROM debian:bookworm
```

Required packages:

| Package                 | Purpose                            |
|-------------------------|------------------------------------|
| `apache2`               | HTTP web server                    |
| `php8.2`                | PHP interpreter                    |
| `libapache2-mod-php8.2` | Apache PHP integration             |
| `php8.2-mysql`          | MySQL/MariaDB PHP extensions       |
| `curl`                  | Downloads the Adminer PHP file     |

Apache runs in the foreground:

```dockerfile
CMD ["apache2ctl", "-D", "FOREGROUND"]
```

### Docker Compose

Adminer has its own container and shares the internal Docker network with MariaDB.

```yaml
adminer:
  image: adminer:inception
  container_name: adminer
  build:
    context: ./requirements/bonus/adminer
  networks:
    - inception
  depends_on:
    - mariadb
```

**Key concept:** `depends_on` controls startup order but does not guarantee that MariaDB is ready.

## 4. Accessing Adminer

Open:

https://localhost:8443/bonus-adminer/

### Database Login

| Field     | Value                                    |
|-----------|------------------------------------------|
| System    | MySQL                                    |
| Server    | `mariadb`                                |
| Username  | `wp_user`                                |
| Password  | Contents of `secrets/db_password.txt`    |
| Database  | `wordpress`                              |

### Credentials

| Account   | Purpose                         | Secret File                     |
|-----------|---------------------------------|---------------------------------|
| `wp_user` | WordPress and Adminer access    | `secrets/db_password.txt`       |
| `root`    | MariaDB administration          | `secrets/db_root_password.txt`  |

**Why is the server `mariadb`?**

Docker's internal DNS resolves the MariaDB service name to its container IP address.

**Why use `wp_user` instead of root?**

The application account has permissions for the WordPress database without requiring full database administrator access.

## 5. NGINX Reverse Proxy

Adminer is accessible through NGINX rather than a directly published Apache port.

```nginx
location = /bonus-adminer {
    return 301 /bonus-adminer/;
}

location ^~ /bonus-adminer/ {
    proxy_pass http://adminer/;
}
```

- `location` matches the requested URL.
- `proxy_pass` forwards requests to Adminer.
- `http://adminer/` uses Docker service-name resolution.
- NGINX provides the external HTTPS connection.
- Apache handles Adminer requests internally.

**Key concept:** A reverse proxy forwards client requests to another server.

## 6. Useful Commands

```bash
# Start Adminer
docker compose -f srcs/docker-compose.yml up -d adminer

# Rebuild Adminer
docker compose -f srcs/docker-compose.yml up -d --build adminer

# Check container status
docker ps

# View logs
docker logs adminer

# Open container shell
docker exec -it adminer bash

# Check PHP version
docker exec adminer php -v

# Check mysqli extension
docker exec adminer php -m | grep mysqli

# Check Apache modules
docker exec adminer apache2ctl -M | grep php

# Stop Adminer
docker compose -f srcs/docker-compose.yml stop adminer
```

## 7. Security and Persistence

- Adminer does not replace MariaDB.
- Adminer does not require its own database volume.
- Database data persists in the MariaDB volume.
- MariaDB port 3306 does not need to be published to the host.
- Adminer should use the application database account for routine access.
- Database passwords must not be committed to Git.
- Adminer access should be restricted because it can modify or delete database records.

## 8. Static vs Dynamic Websites

| Static Website                    | Dynamic Website                         |
|-----------------------------------|-----------------------------------------|
| Predefined HTML/CSS content       | Content generated at request time       |
| Does not require a database       | May use a database                      |
| Same content until files change   | Content can change based on data/users  |
| Example: Inception static website | Example: WordPress and Adminer          |

**Key concept:** Static websites serve predefined files; dynamic websites can generate content using application logic and data.

## 10. Inception Evaluation Questions

**Q: What is Adminer?**

A lightweight web application for managing databases through a browser.

**Q: Why use Adminer?**

To inspect WordPress tables, execute SQL queries, and manage database records without using the command-line client.

**Q: Does Adminer store the database?**

No. MariaDB stores the data; Adminer only connects to it.

**Q: Why does Adminer need PHP?**

Adminer is written in PHP and requires a PHP interpreter.

**Q: Why does Adminer need mysqli?**

To establish database connections between PHP and MariaDB.

**Q: Why does Adminer need Apache?**

Apache serves the Adminer PHP application over HTTP.

**Q: Why use NGINX as a reverse proxy?**

To provide a single HTTPS entry point while forwarding Adminer requests to its internal container.

**Q: Why use `mariadb` as the database server address?**

Docker resolves the service name through its internal DNS.

**Q: Does Adminer need a Docker volume?**

Not for the database itself. Persistent database storage is handled by MariaDB.

**Q: Why run Adminer in a separate container?**

To isolate database administration from WordPress and MariaDB, following the one-service-per-container architecture.

## 11. Quick Summary

- Adminer = Web-based database management
- Apache = HTTP server
- PHP = Executes Adminer
- `mysqli` = PHP database extension
- MariaDB = Stores the database
- NGINX = HTTPS reverse proxy
- `mariadb` = Database hostname
- `3306` = MariaDB TCP port
- `wp_user` = Database application user
- `wordpress` = Database name
- `/bonus-adminer/` = Adminer URL
- Docker network = Internal service communication
- Docker volume = Persistent database storage

**One-sentence summary:**

Adminer runs in its own Docker container using Apache and PHP, connects to MariaDB through the internal Docker network, and provides a browser-based interface for managing the WordPress database.
