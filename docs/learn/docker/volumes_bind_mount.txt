Persistent data in Inception means data 
that survives when containers are stopped, removed, or recreated

It can be stored using either Docker named volumes or bind mounts.


1. Docker named volumes [INCEPTION]

    volumes:
        mariadb:
        wordpress:
        
    Docker manages these volumes.

    Data survives:
        docker compose down
        docker compose up -d

    But named volumes are removed when you run
        docker compose down --volumes

        
2. Bind mounts
    services:
        mariadb:
            volumes:
               - mariadb:/var/lib/mysql

    volumes:
        mariadb:
            driver: local
            driver_opts:
                type: none
                o: bind
                device: /home/yourlogin/data/mariadb
        
    This is a Docker named volume backed by a host directory using a bind mount

For Inception

    DATA_DIR = $(HOME)/data

    ~/data/
    ├── mariadb/
    └── wordpress/


    These directories hold your persistent database and WordPress files, 
    assuming your Compose volume configuration points to them.


    So you have both concepts:
   - Named volume: mariadb
   - Host storage: /home/yourlogin/data/mariadb
   - Container storage: /var/lib/mysql

    Even if you run, actual files in /home/yourlogin/data/mariadb can remain because they're stored in a host directory.
        docker compose down --volumes

    Container: Runs your application.
    Volume: Stores data outside the container's writable layer.
    Persistent data: The actual files that survive container recreation.
    Bind mount: Connects storage to a host directory.

    MariaDB database files and WordPress website files are your two main persistent datasets, stored through Docker volumes.


----

DIRECT BIND MOUNT

services:
  mariadb:
    volumes:
      - /home/nchairun/data/mariadb:/var/lib/mysql

This directly mounts a host directory into the container. It doesn't declare a named volume.


NAMED VOLUME USING LOCAL DRIVER

services:
  mariadb:
    volumes:
      - mariadb:/var/lib/mysql

volumes:
  mariadb:
    driver: local
    driver_opts:
      type: none
      o: bind
      device: /home/nchairun/data/mariadb

Here, mariadb is a named Docker volume, but its storage is backed by a host directory.


This is the pattern commonly used for the 42 Inception requirement that data be stored under /home/login/data on the host.

The o: 
    bind option still uses bind-mount mechanics internally. 
    Whether that is permitted depends on the exact wording of your Inception subject.

A Docker image is a blueprint used to create Docker containers. 

Think of it this way:
- Dockerfile = Instructions for building something.
- Docker image = The finished package containing everything needed to run your application.
- Docker container = A running instance created from that image.


---

Dockerfile
Instructions: install Debian, MariaDB, copy configuration files
    |
docker build
    |
Docker image
mariadb:inception
    |
docker compose up
    |
Docker container
mariadb running as a database server


Docker image	        Container
mariadb:inception	    mariadb
wordpress:inception	    wordpress
nginx:inception	        nginx
adminer:inception	    adminer


----

                Image	            Container	            Volume
Purpose 	    Package application	Run application	        Store persistent data
Example	        MariaDB image	    Running MariaDB server	Database files
Can delete?	    Yes	                Yes	                    Yes, but data may be lost
Stores 	        No	                Not reliably	        Yes
Persistent DB


For example, if you delete your MariaDB container but keep its named volume, you can create a new MariaDB container and still have your database.

Commands to remember
docker images       # List images
docker ps           # List running containers
docker ps -a        # List all containers
docker volume ls    # List volumes

--build tells Docker Compose to build the images before starting the containers.


---

build creates Docker images.

up creates and starts Docker containers.
