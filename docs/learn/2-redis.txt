he main point of Redis in Inception is 
to make WordPress faster by caching frequently accessed data in memory instead of repeatedly querying MariaDB.

Without Redis:

    WordPress → MariaDB → Get data
    WordPress → MariaDB → Get same data again


With Redis:
    WordPress → Redis → Cache HIT → Return data quickly
                    |
                    └── Cache MISS → MariaDB → Cache result


---

1. MariaDB stores permanent data.
2. Redis caches frequently accessed data in RAM.
3. WordPress Redis Object Cache plugin connects WordPress to Redis.

---

How do you prove it works?
    docker exec redis redis-cli INFO stats | grep keyspace_hits


Your result was keyspace_hits:7,
 meaning Redis successfully returned cached data seven times.

REDIS OBJECT CACHE - INCEPTION BONUS
===============================================================================

1. WHAT IS REDIS?
-------------------------------------------------------------------------------
Redis (Remote Dictionary Server) is an in-memory key-value data store.

In Inception, Redis caches WordPress objects to reduce repeated database
queries and improve performance.

Redis does NOT replace MariaDB.

MariaDB = Persistent database storage
Redis   = Temporary in-memory cache


2. ARCHITECTURE
-------------------------------------------------------------------------------
Browser
   |
   v
NGINX (HTTPS / TLS)
   |
   v
WordPress (PHP-FPM)
   |
   +------> MariaDB :3306 (Persistent database)
   |
   +------> Redis   :6379 (Object cache)

All containers communicate through the internal Docker network "inception".

Redis does not publish a port to the host.


3. REDIS DOCKERFILE
-------------------------------------------------------------------------------
Location: srcs/requirements/bonus/redis/Dockerfile

FROM debian:bookworm

RUN apt-get update && \
    apt-get install -y --no-install-recommends redis-server && \
    rm -rf /var/lib/apt/lists/*

EXPOSE 6379

CMD ["redis-server", "--bind", "0.0.0.0", "--protected-mode", "no", \
     "--save", "", "--appendonly", "no"]

Explanation:
- redis-server       : Starts Redis in the foreground.
- --bind 0.0.0.0     : Allows connections from WordPress.
- --protected-mode no: Allows internal network access without authentication.
- --save ""          : Disables periodic disk snapshots.
- --appendonly no    : Disables append-only persistence.
- EXPOSE 6379        : Documents the Redis port; does not publish it.

Security:
This configuration is intended only for an isolated, trusted Docker network.
Do not expose this unauthenticated Redis service publicly.

5. WORDPRESS CONFIGURATION
-------------------------------------------------------------------------------
Install the Redis PHP extension in the WordPress Dockerfile:

    php8.2-redis

After creating wp-config.php, add to WordPress init.sh:

    wp config set WP_REDIS_HOST "redis" --allow-root
    wp config set WP_REDIS_PORT 6379 --raw --allow-root

These commands generate PHP configuration constants:

    define('WP_REDIS_HOST', 'redis');
    define('WP_REDIS_PORT', 6379);

IMPORTANT:
PHP define() statements belong in PHP files, not directly in Bash scripts.


6. WORDPRESS REDIS PLUGIN
-------------------------------------------------------------------------------
Install and activate:

docker exec wordpress wp plugin install redis-cache --activate --allow-root

Enable object caching:

docker exec wordpress wp redis enable --allow-root

Check status:

docker exec wordpress wp redis status --allow-root

Expected:
    Status: Connected
    Drop-in: Valid
    Disabled: No
    Errors: []

For automatic installation on fresh setups, add to init.sh after WordPress
core installation:

if ! wp plugin is-installed redis-cache --allow-root; then
    wp plugin install redis-cache --activate --allow-root
fi

wp plugin activate redis-cache --allow-root --quiet
wp redis enable --allow-root

Check cache statistics:

docker exec redis redis-cli INFO stats | grep -E 'keyspace_hits|keyspace_misses'

Actual test result:
    keyspace_hits:7
    keyspace_misses:24

Cache hit rate:
    7 / (7 + 24) * 100 = 22.6%

keyspace_hits   = Requested data found in Redis.
keyspace_misses = Requested data not found in Redis.

Cache hits greater than zero confirm that Redis has served cached data.
Repeated WordPress requests should generally increase the hit counter.


8. WHY NO REDIS VOLUME?
-------------------------------------------------------------------------------
Redis stores temporary cache data.

If Redis restarts, the cache can be rebuilt from WordPress and MariaDB.

Therefore, persistent storage is not required for this setup.


9. EVALUATION QUESTIONS
-------------------------------------------------------------------------------
Q: Why did you choose Redis?
A: To cache WordPress objects in memory, reducing repeated database queries.

Q: Does Redis replace MariaDB?
A: No. MariaDB stores permanent data; Redis caches temporary data.

Q: Which port does Redis use?
A: TCP port 6379.

Q: How does WordPress connect to Redis?
A: Through the Docker network using hostname "redis" and port 6379.

Q: What is the Redis Object Cache plugin?
A: A WordPress plugin that integrates WordPress object caching with Redis.

Q: What is the object-cache.php drop-in?
A: A WordPress file that redirects object-cache operations to Redis.

Q: How do you prove Redis works?
A: Check PONG, WordPress connection status, and keyspace_hits.

Q: What happens if Redis loses its cache?
A: WordPress can regenerate cached objects from its underlying data.

Q: Why isn't Redis accessible from the host?
A: It is an internal service. No host port mapping is configured.

Q: Why run Redis in the foreground?
A: Docker monitors the main process. If Redis exits, the container stops.
