GOACCESS - INCEPTION BONUS

Purpose:
Analyze NGINX access logs and generate a web analytics dashboard.

Architecture:
Browser -> NGINX -> WordPress
              |
              v
         nginx_logs
              |
              v
         GoAccess
              |
              v
       goaccess_report
              |
              v
       NGINX -> Browser

Docker:
- Base image: debian:bookworm
- Package: goaccess
- Own Dockerfile and container
- Network: inception

Shared volumes:
nginx_logs:
  NGINX writes access.log
  GoAccess reads access.log (read-only)

goaccess_report:
  GoAccess generates index.html
  NGINX serves index.html (read-only)

NGINX:
access_log /var/log/nginx/access.log combined;

location /bonus-goaccess/ {
    alias /var/www/goaccess/;
    index index.html;
}

GoAccess command:
goaccess /var/log/nginx/access.log \
  --log-format=COMBINED \
  -o /var/www/goaccess/index.html

Dashboard:
https://localhost:8443/bonus-goaccess/

Features:
- Total HTTP requests
- Visitors
- Most requested URLs
- HTTP status codes (200, 301, 404, 500)
- Bandwidth usage
- Traffic statistics

Testing:
make up
docker logs goaccess
docker exec nginx tail /var/log/nginx/access.log
docker exec goaccess ls /var/www/goaccess/index.html

Generate traffic:
curl -k https://localhost:8443/
curl -k https://localhost:8443/posts/
curl -k https://localhost:8443/not-found

Evaluation:
Q: What is GoAccess?
A: A web log analyzer that generates traffic statistics.

Q: Does GoAccess replace NGINX?
A: No. NGINX serves requests; GoAccess analyzes its logs.

Q: Does GoAccess access MariaDB?
A: No. It reads NGINX access logs.

Q: Why use shared volumes?
A: Containers share log and report files without copying them.

Q: Is the dashboard real-time?
A: This implementation regenerates a static report every 10 seconds.

Q: Why is it useful?
A: It helps analyze traffic, popular URLs, errors, and bandwidth.

Security:
Restrict dashboard access because logs may contain sensitive data.

https://localhost:8443/bonus-goaccess/

Security note: NGINX access logs can contain visitor IP addresses and requested URLs. This dashboard should not be publicly accessible without authentication. For local evaluation, restrict access appropriately, for example with NGINX allow/deny rules.

Understanding HTTP status codes
Code	Meaning
200	Success, page or file delivered
301	Permanent redirect
302	Temporary redirect
403	Access forbidden
404	Page or file not found
500	Internal server error
502	Bad gateway, often a backend communication problem
