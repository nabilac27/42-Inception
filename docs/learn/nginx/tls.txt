TLS (Transport Layer Security) 
is a security protocol that encrypts communication between your browser and a web server.

It's what makes HTTPS secure. 🔒

Without TLS: HTTP
    Browser                         NGINX
    |                               |
    | ---- Username: admin -------> |
    | ---- Password: 123456 ------> |
    |                               |
    |      Unencrypted data         |


Someone intercepting the network traffic could read your username, password, or other sensitive information.

With TLS: HTTPS
    Browser                         NGINX
    |                               |
    | <---- TLS Handshake --------> |
    |                               |
    | ==== Encrypted connection === |
    |                               |
    | ---- Encrypted data --------> |
    |                               |


Someone intercepting the traffic cannot normally read or modify the encrypted contents.
Three things TLS provides
    1. Encryption    : Prevents others from reading transmitted data.
    2. Integrity     : Detects tampering with transmitted data.
    3. Authentication: Certificates help verify the server's identity.

NGINX handles TLS. WordPress and MariaDB don't need to handle browser HTTPS directly.
Important: 
Your self-signed certificate encrypts traffic, but browsers won't automatically trust its identity.

TLS secures communication between the client and server through encryption, integrity protection, 
and certificate-based authentication. In Inception, NGINX handles TLS and only TLS 1.2 or TLS 1.3 should be accepted.

===============================================================================
    TLS CERTIFICATE VERIFICATION
===============================================================================

1. WHAT IS A SELF-SIGNED CERTIFICATE?
-------------------------------------------------------------------------------

A self-signed certificate is an SSL/TLS certificate signed by its own creator,
rather than by a trusted Certificate Authority (CA).

It can encrypt communication between the browser and the server, but browsers
do not automatically trust the identity of the server.

In Inception:
- NGINX handles HTTPS connections.
- TLS 1.2 and TLS 1.3 should be supported.
- The certificate is generated locally.
- The certificate identifies nchairun.42.fr.
- Browsers may display a security warning.

IMPORTANT:
Encryption and certificate trust are two different things.


2. CHECK THE CERTIFICATE IN A BROWSER
-------------------------------------------------------------------------------

Open:

    https://localhost:8443

Expected behavior:
- Firefox may display "Warning: Potential Security Risk Ahead".
- The browser does not recognize the certificate as trusted.
- The connection can still use TLS encryption.

To inspect the certificate:
1. Open the HTTPS website.
2. Click "Advanced" on the warning page.
3. Inspect the certificate information.

For local development, you can accept a temporary exception if you trust
your own server.


3. CHECK THE CERTIFICATE WITH OPENSSL
-------------------------------------------------------------------------------

Command:

    openssl s_client -connect localhost:8443 -tls1_2 </dev/null

Example output:

    subject=CN = nchairun.42.fr
    issuer=CN = nchairun.42.fr
    Verify return code: 18 (self-signed certificate)

Explanation:

subject:
    The identity that the certificate claims to represent.

issuer:
    The identity that signed the certificate.

Verify return code: 18:
    OpenSSL detected a self-signed certificate that it could not validate
    through its trusted certificate chain.

When subject and issuer are identical, this is consistent with a
self-signed certificate.


4. CHECK WITH CURL
-------------------------------------------------------------------------------

TEST 1: WITHOUT BYPASSING CERTIFICATE VERIFICATION

    curl -I https://localhost:8443

Expected result:

    curl: (60) SSL certificate problem: self-signed certificate

Explanation:
    curl cannot verify the certificate using its trusted authorities.


TEST 2: WITH CERTIFICATE VERIFICATION DISABLED

    curl -k -I https://localhost:8443

Example successful response:

    HTTP/1.1 200 OK
    Server: nginx

Explanation:
    -k tells curl to skip certificate verification.

IMPORTANT:
    -k does NOT disable TLS encryption.
    -k disables certificate identity verification.
    Use it only for trusted local testing.


5. HOW TO MAKE THE CERTIFICATE TRUSTED
-------------------------------------------------------------------------------

OPTION 1: Keep the self-signed certificate
    - Accept the browser warning during local development.
    - No additional configuration is necessary.

OPTION 2: Import the certificate into your local trust store
    - Verify the certificate is genuinely yours.
    - Add it to the appropriate trusted certificate store.
    - Trust applies only to systems configured to recognize it.

OPTION 3: Use mkcert
    - Generate locally trusted development certificates.
    - Install mkcert's local Certificate Authority.
    - Generate certificates for your development domain.

For the Inception project, a publicly trusted certificate is not necessary
just to demonstrate that HTTPS encryption works.


6. TLS ENCRYPTION VS CERTIFICATE TRUST
-------------------------------------------------------------------------------

WITHOUT TLS (HTTP):

    Browser --------------------------> NGINX
                Plaintext data

    Network observers may read or modify transmitted information.


WITH TLS BUT AN UNTRUSTED CERTIFICATE (HTTPS):

    Browser ===== Encrypted ========> NGINX
                TLS connection

    Data is encrypted, but the browser cannot independently verify
    that the server is genuinely the intended server.

    This leaves a risk of impersonation or man-in-the-middle attacks.


WITH TLS AND A TRUSTED CERTIFICATE (HTTPS):

    Browser ===== Encrypted ========> NGINX
           Verified server identity

    - Data is encrypted.
    - Data integrity is protected.
    - The server's identity is authenticated through certificate validation.

8. IMPORTANT COMMANDS FOR 42 EVALUATION
-------------------------------------------------------------------------------

Check NGINX TLS configuration:

    make check-tls

Test TLS 1.2:

    openssl s_client -connect localhost:8443 -tls1_2 </dev/null

    openssl s_client -connect localhost:8443 -tls1_3 </dev/null

9. QUESTIONS FOR INCEPTION EVALUATION
-------------------------------------------------------------------------------

Q: What is TLS?

A: TLS stands for Transport Layer Security. It encrypts communication
   between a client and server, protects data integrity, and supports
   server authentication through certificates.


Q: What is the difference between HTTP and HTTPS?

A: HTTP transfers data without TLS encryption.
   HTTPS uses HTTP over TLS to protect communication.


Q: Why does your browser show a certificate warning?

A: Because my NGINX certificate is self-signed and is not trusted by
   the browser's default certificate authorities.


Q: Does a self-signed certificate still encrypt traffic?

A: Yes. TLS encryption can work with a self-signed certificate,
   but the browser cannot automatically verify the server's identity.


Q: What does curl -k do?

A: It disables certificate verification, but the connection still
   uses TLS encryption.


Q: What does NGINX do in your Inception project?

A: NGINX accepts HTTPS connections, handles TLS encryption, and forwards
   PHP requests to WordPress through FastCGI.


Q: Which TLS versions should Inception support?

A: TLS 1.2 and TLS 1.3.
