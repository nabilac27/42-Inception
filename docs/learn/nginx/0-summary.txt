# NGINX, TLS & Networking - Inception Evaluation Cheat Sheet

## 1. What is NGINX?

NGINX is a web server and reverse proxy.

In Inception, NGINX:
- Acts as the single entry point for the application.
- Accepts HTTPS connections.
- Handles TLS encryption.
- Serves static files.
- Forwards PHP requests to WordPress PHP-FPM.
- Can reverse-proxy requests to bonus services.

**Key concept:** NGINX handles incoming web requests, while PHP-FPM executes WordPress PHP code.

## 2. Inception Architecture

```text
Browser
   |
   | HTTPS (TLS 1.2 / TLS 1.3)
   v
NGINX :443
   |
   | FastCGI TCP :9000
   v
WordPress (PHP-FPM)
   |
   | MariaDB protocol TCP :3306
   v
MariaDB
   |
   v
/var/lib/mysql
   |
   v
Docker Volume
```

Only NGINX needs a published port for the mandatory project.

WordPress and MariaDB communicate through the internal Docker network.

## 3. What is TLS?

TLS stands for Transport Layer Security.

TLS provides three security properties:

| Property       | Purpose                                      |
|----------------|----------------------------------------------|
| Encryption     | Protects transmitted data from being read    |
| Integrity      | Detects modifications during transmission    |
| Authentication | Helps verify the server's identity           |

**HTTPS = HTTP over TLS**

### NGINX TLS Configuration

```nginx
listen 443 ssl;
ssl_protocols TLSv1.2 TLSv1.3;
```

- `listen 443 ssl;` enables HTTPS on port 443.
- `ssl_protocols` restricts accepted TLS versions.

**Key concept:** Inception requires TLS 1.2 and TLS 1.3.

## 4. TLS Certificates

A TLS certificate contains information about the server's identity and public key.

NGINX uses two files:

| File                           | Purpose                    |
|--------------------------------|----------------------------|
| `/etc/nginx/ssl/nginx.crt`     | Public certificate         |
| `/etc/nginx/ssl/nginx.key`     | Private key                |

NGINX configuration:

```nginx
ssl_certificate /etc/nginx/ssl/nginx.crt;
ssl_certificate_key /etc/nginx/ssl/nginx.key;
```

**Key concept:** The certificate can be shared publicly; the private key must remain secret.

## 5. Self-Signed Certificates

A self-signed certificate is signed by its own creator instead of a trusted Certificate Authority (CA).

| Self-Signed Certificate         | CA-Signed Certificate            |
|---------------------------------|----------------------------------|
| Signed by its creator           | Signed by a trusted CA           |
| Can provide TLS encryption      | Provides TLS encryption          |
| Not trusted automatically       | Trusted if validation succeeds   |
| Suitable for local testing      | Common for production websites   |

**Important:** Encryption and certificate trust are different.

A self-signed certificate can encrypt traffic, but browsers cannot automatically verify the server's identity.

## 6. NGINX Configuration Syntax

```nginx
server {
    listen 443 ssl;
    server_name nchairun.42.fr;
}
```

| Syntax        | Meaning                                  |
|---------------|------------------------------------------|
| `server {}`   | Defines a virtual server                 |
| `listen`      | Specifies listening port and protocol   |
| `server_name` | Specifies the hostname                   |
| `location`    | Matches request URLs                     |
| `{ }`         | Groups directives                        |
| `;`           | Ends a directive                         |

**Key concept:** `server_name` does not configure DNS. DNS or `/etc/hosts` must resolve the hostname.

## 7. NGINX Document Root

```nginx
root /var/www/html;
index index.php;
```

- `root` specifies the directory containing website files.
- `index` specifies the default file for directory requests.

NGINX and WordPress can access the same WordPress files through a shared Docker volume.

## 8. WordPress URL Routing

```nginx
location / {
    try_files $uri $uri/ /index.php?$args;
}
```

`try_files` checks:

1. Whether the requested file exists.
2. Whether the requested directory exists.
3. Otherwise, internally redirects to `index.php`.

Example:

```text
https://nchairun.42.fr/sample-page/
                 |
                 v
          NGINX try_files
                 |
                 v
             index.php
                 |
                 v
             WordPress
```

**Key concept:** WordPress uses dynamic URLs that may not correspond to physical directories.

## 9. NGINX and PHP-FPM

PHP-FPM stands for PHP FastCGI Process Manager.

NGINX does not execute PHP itself. It forwards PHP requests to PHP-FPM using FastCGI.

```nginx
location ~ \.php$ {
    include fastcgi_params;
    fastcgi_pass wordpress:9000;
    fastcgi_param SCRIPT_FILENAME $document_root$fastcgi_script_name;
    fastcgi_param HTTPS on;
    fastcgi_param HTTP_HOST $http_host;
    fastcgi_param SERVER_PORT 8443;
}
```

| Directive             | Purpose                                      |
|-----------------------|----------------------------------------------|
| `location ~ \.php$`   | Matches URLs ending in `.php`                |
| `include`             | Loads standard FastCGI parameters            |
| `fastcgi_pass`        | Sends requests to PHP-FPM                    |
| `SCRIPT_FILENAME`     | Provides the PHP script's filesystem path    |
| `HTTPS on`            | Indicates the original request used HTTPS    |
| `HTTP_HOST`           | Passes the original hostname and port        |
| `SERVER_PORT 8443`    | Supplies the external testing port           |

**Key concept:** NGINX communicates with WordPress PHP-FPM over TCP port 9000 in this setup.

## 10. Common Network Ports

| Port   | Purpose                  |
|--------|--------------------------|
| `22`   | SSH                      |
| `80`   | HTTP                     |
| `443`  | HTTPS                    |
| `3306` | MariaDB                  |
| `9000` | PHP-FPM                  |
| `8443` | Alternative HTTPS port   |

Docker Compose port mapping for local testing:

```yaml
ports:
  - "8443:443"
```

- `8443` = Host port.
- `443` = Container port.

For evaluation, a configuration may use:

```yaml
ports:
  - "443:443"
```

**Key concept:** The left side is the host port; the right side is the container port.

## 11. TCP vs UDP

| TCP                                  | UDP                              |
|--------------------------------------|----------------------------------|
| Connection-oriented                  | Connectionless                   |
| Reliable delivery                    | No built-in delivery guarantee   |
| Preserves data order                 | No built-in ordering guarantee   |
| Used for HTTPS and MariaDB           | Commonly used for DNS and games  |

TCP stands for Transmission Control Protocol.

UDP stands for User Datagram Protocol.

**Key concept:** Inception's main application connections use TCP.

## 12. IP Addresses and Ports

An IP address identifies a network interface.

A port identifies a network service.

Example:

```text
mariadb:3306
   |      |
   |      +-- MariaDB TCP port
   |
   +--------- Docker service hostname
```

Docker's internal DNS resolves `mariadb` to the appropriate container IP address.

## 13. TCP vs Unix Socket

| TCP Connection                     | Unix Socket                       |
|------------------------------------|-----------------------------------|
| Communicates over a network        | Local inter-process communication |
| Uses IP address and port           | Uses filesystem socket path       |
| Example: `mariadb:3306`            | Example: `/run/mysqld/mysqld.sock`|
| Used by WordPress                  | Used by local MariaDB clients     |

**Key concept:** WordPress uses TCP to connect to MariaDB in another container, while local MariaDB clients can use a Unix socket.

## 14. MariaDB Bind Address

MariaDB configuration:

```ini
[mysqld]
bind-address = 0.0.0.0
port         = 3306
socket       = /run/mysqld/mysqld.sock
datadir      = /var/lib/mysql
```

| Address     | Meaning                                    |
|-------------|--------------------------------------------|
| `127.0.0.1` | Listen only on the container's loopback    |
| `0.0.0.0`   | Listen on all container IPv4 interfaces    |

**Key concept:** `0.0.0.0` allows WordPress to connect through the Docker network, but does not itself publish MariaDB's port to the host.

## 15. Dockerfile vs Entrypoint

| Dockerfile                       | Entrypoint Script                  |
|----------------------------------|------------------------------------|
| Defines how an image is built    | Runs when the container starts     |
| Installs software                | Initializes application state      |
| Copies configuration files       | Starts application processes       |
| Executes during image build      | Executes during container runtime  |

Example Dockerfile:

```dockerfile
FROM debian:bookworm

RUN apt-get update && \
    apt-get install -y nginx openssl

COPY conf/default.conf /etc/nginx/conf.d/default.conf

CMD ["nginx", "-g", "daemon off;"]
```

**Key concept:** Dockerfile = build time; entrypoint = runtime.

## 16. Docker Image Layers

Docker images are built using reusable layers.

```text
Base Image
    |
    v
Package Installation
    |
    v
Copied Configuration
    |
    v
Final Docker Image
```

- Layers are reusable.
- Docker can cache unchanged build steps.
- Changing an instruction can invalidate the cache for later steps.

**Key concept:** Docker uses image layers to make builds efficient and reusable.

## 17. ENTRYPOINT vs CMD

| ENTRYPOINT                        | CMD                                  |
|-----------------------------------|--------------------------------------|
| Defines the main executable       | Supplies default command or arguments|
| Usually kept when arguments added | Easily overridden at runtime         |
| Often launches an init script     | Often starts the main service         |

Example:

```dockerfile
ENTRYPOINT ["/usr/local/bin/init.sh"]
CMD ["nginx", "-g", "daemon off;"]
```

The entrypoint receives the CMD arguments.

**Key concept:** ENTRYPOINT defines what runs; CMD provides default execution arguments.

## 18. Why Use `exec`?

Without `exec`:

```text
PID 1: Shell
         |
         v
      NGINX
```

With `exec`:

```text
PID 1: NGINX
```

Example:

```bash
exec nginx -g 'daemon off;'
```

- Replaces the shell process.
- Makes NGINX the container's main process.
- Allows Docker stop signals to reach NGINX directly.

**Key concept:** `exec` helps the main application handle container lifecycle signals correctly.

## 19. Useful TLS Verification Commands

```bash
# Test TLS 1.2
openssl s_client -connect localhost:8443 -tls1_2 </dev/null

# Test TLS 1.3
openssl s_client -connect localhost:8443 -tls1_3 </dev/null

# Test TLS 1.1 (should fail)
openssl s_client -connect localhost:8443 -tls1_1 </dev/null

# Test certificate validation
curl -I https://localhost:8443

# Test HTTPS without certificate validation
curl -k -I https://localhost:8443

# Inspect NGINX configuration
docker exec nginx nginx -T

# Check NGINX configuration syntax
docker exec nginx nginx -t
```

`curl -k` disables certificate verification, not TLS encryption.

## 20. Inception Evaluation Questions

**Q: What is TLS?**

TLS is a security protocol that provides encryption, integrity protection, and authentication for network communication.

**Q: What is HTTPS?**

HTTP over TLS.

**Q: Why use TLS 1.2 and TLS 1.3?**

They are the TLS versions required by Inception and provide modern security protections.

**Q: What is a self-signed certificate?**

A certificate signed by its creator rather than a trusted Certificate Authority.

**Q: Why does the browser show a certificate warning?**

Because the self-signed certificate is not automatically trusted.

**Q: What is NGINX?**

A web server and reverse proxy that handles HTTPS requests and forwards PHP requests to PHP-FPM.

**Q: What is PHP-FPM?**

A process manager that executes PHP scripts using the FastCGI protocol.

**Q: Why use port 9000?**

It is the TCP port configured for communication between NGINX and PHP-FPM.

**Q: Why use `try_files`?**

To route requests for WordPress dynamic URLs to `index.php` when no matching physical file or directory exists.

**Q: Why is NGINX the only public entry point?**

To centralize HTTPS access and avoid unnecessarily exposing internal services.

**Q: What is TCP?**

A transport protocol that provides reliable, ordered communication.

**Q: What is UDP?**

A connectionless transport protocol without built-in reliability or ordering guarantees.

**Q: What is the difference between TCP and a Unix socket?**

TCP supports network communication using IP addresses and ports; Unix sockets support local communication using socket paths.

**Q: Why use `exec` in a container?**

To replace the startup shell with the main server process so it becomes PID 1.

**One-sentence summary:**

NGINX acts as Inception's HTTPS entry point, uses TLS 1.2 or 1.3 to secure browser connections, forwards PHP requests to WordPress through FastCGI, and relies on Docker networking for internal service communication.
