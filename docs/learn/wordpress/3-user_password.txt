WordPress has 6 default user roles, each with different permissions.

+---------------+--------------------------------------------------------------------------+
| Role          | Permissions                                                              |
+---------------+--------------------------------------------------------------------------+
| Administrator | Full control over users, themes, plugins, settings, posts, and comments. |
| Editor        | Can manage posts from all authors and moderate comments.                |
| Author        | Can write, publish, edit, and delete their own posts.                    |
| Contributor   | Can write and edit their own posts but cannot publish them.              |
| Subscriber    | Can log in, manage their profile, and write comments.                    |
+---------------+--------------------------------------------------------------------------+

Note: Super Admin is only available in WordPress Multisite installations.

Persistent data:
- information that survives even when Docker containers are 
    stopped, removed, or recreated.

Main idea:
- Containers are temporary. 
- Your database and WordPress files should not be.

---

Without persistent data
    Imagine you install WordPress, create an administrator, and publish three posts.

    WordPress container
    Posts, users, settings stored only inside container

    Container removed
    Data lost

    If the data exists only inside the container's writable filesystem, removing that container removes its data.



With persistent data
    Your Inception project uses two Docker volumes backed by directories on your computer.

    ~/data/
    ├── mariadb/
    │   └── Database files
    └── wordpress/
        └── WordPress files

    docker-compose.yml connects them to the containers:
    volumes:
    mariadb_data:
        driver: local
        driver_opts:
        type: none
        o: bind
        device: ${HOME}/data/mariadb

    wordpress_data:
        driver: local
        driver_opts:
        type: none
        o: bind
        device: ${HOME}/data/wordpress


What is actually saved?
MariaDB ~/data/mariadb	            WordPress ~/data/wordpress
WordPress database	                WordPress core files
User accounts and password hashes	Themes and plugins
Posts and comments	                Uploaded images
Website settings	                wp-config.php

WordPress posts and users are stored in MariaDB, 
not directly in the WordPress files directory.


Command	    Containers	            Persistent data
make	    Start	                Kept
make down	Removed	                Kept
make up	    Recreated if needed	    Kept
make clean	Removed	                Kept
make fclean	Removed	                Deleted by your rm -rf
make re	    Rebuilt	                Deleted and recreated


docker compose down --volumes removes the Compose-managed volume definitions, 
but does not delete the contents of your host directories when using your bind-backed volume configuration


make down + make = restart without losing data.
make re          = fresh installation, deleting previous data with your current Makefile.
