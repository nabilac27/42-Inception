tl;dr

  MariaDB is the database server for WordPress. 
  It runs in its own container, listens on port 3306 inside the Docker network, 
  and its data is stored persistently in a Docker volume.

    MariaDB = database server

    mariadbd
        = server process

    3306
        = MariaDB TCP port

    /var/lib/mysql
        = database data

    /run/mysqld/mysqld.sock
        = local Unix socket

    mysql Linux user
        = runs MariaDB safely

    0.0.0.0
        = accept connections through container network

    mariadb-install-db
        = initialize new database directory

    MariaDB user
        = WordPress uses it to access DB

    Docker volume
        = keeps DB after container deletion

    exec mariadbd
        = MariaDB becomes PID 1

1. What even is MariaDB?
    MariaDB is a relational database management system.

    Think of your architecture:
    Browser
    │
    ▼
    NGINX
    │
    ▼
    WordPress
    │
    ▼
    MariaDB

    WordPress is the application.

    MariaDB is where WordPress stores structured information such as:
        users
        posts
        comments
        settings
        categories
        plugin data

    Example:
        users table

        +----+----------+-------------------+
        | id | username | email             |
        +----+----------+-------------------+
        | 1  | nchairun | example@email.com |
        | 2  | bob      | bob@email.com     |
        +----+----------+-------------------+
    
    WordPress asks MariaDB questions and MariaDB returns answers

2. MariaDB vs SQL
    MariaDB is database software.
    SQL is the language you use to communicate with a relational database.

    MariaDB = program
    SQL     = language you speak to the program

    For example:
      CREATE DATABASE wordpress;

    That's SQL being executed by MariaDB.

    
3. Server vs client
  This is another important distinction.
  You installed:
    mariadb-server

  The actual database server process is:
    mariadbd

  It sits there waiting for connections:
              MariaDB server
                mariadbd
                    │
            listening on :3306
                    │
          ┌──────────┴──────────┐
          │                     │
      WordPress            mariadb CLI

  There's also a client command:
    mariadb

  You use that to connect to the server.
  So:
    mariadbd = SERVER
    mariadb  = CLIENT

  This distinction is fantastic evaluation ammunition.

4. What is a database?
    A MariaDB server can contain multiple databases.

    MariaDB Server
    │
    ├── mysql
    ├── information_schema
    ├── performance_schema
    │
    └── wordpress      ← we'll create this
          │
          ├── wp_users
          ├── wp_posts
          ├── wp_comments
          ├── wp_options
          └── ...

    We're eventually going to create something like:
      CREATE DATABASE wordpress;

    WordPress will then use that database.


5. Tables
  Inside a database are tables.

  wp_posts

  +----+--------------------+-------------+
  | id | title              | author      |
  +----+--------------------+-------------+
  | 1  | Hello World        | nchairun    |
  | 2  | Learning Docker    | nchairun    |
  +----+--------------------+-------------+


  Think:
    MariaDB server
        ↓
    database
        ↓
    tables
        ↓
    rows + columns

  You don't manually create WordPress's tables. WordPress does that when it installs.

6. MariaDB users

  MariaDB has its own users.

  For example, later we might create:
    CREATE USER 'wpuser'@'%' IDENTIFIED BY 'password';

  This does NOT create a WordPress website user.

  This distinction is extremely important:
  MariaDB user
      │
      │ used by WordPress software
      │ to connect to database
      ▼
  wpuser


  WordPress user
      │
      │ human account
      │
      ▼
  nchairun

  So if your evaluator asks:
  "Why do you have a MariaDB user?"

  You can say:
  WordPress needs database credentials to connect to MariaDB. 
  The MariaDB user is given permissions on the WordPress database.

  The subject separately requires at least two WordPress users, one being an administrator.


7. Permissions

  We don't want WordPress to have unlimited access to everything on the MariaDB server.

  Instead:
    MariaDB
    │
    ├── system databases ❌
    │
    ├── other databases  ❌
    │
    └── wordpress        ✅ wpuser

  You'll eventually execute something along the lines of:
    GRANT ALL PRIVILEGES
    ON wordpress.*
    TO 'wpuser'@'%';

  wordpress.* means:
    wordpress database
          .
          *
          ↓
    all tables inside it

8. What does 'wpuser'@'%' mean?

  MariaDB accounts include both:
    username + allowed host

  For example:
    'wpuser'@'localhost'

  means that user connects locally.

  But WordPress is going to be in another container.
    WordPress container
            │
            │ network
            ▼
    MariaDB container

  So you'll commonly encounter:
    'wpuser'@'%'

  % is a wildcard for hosts.
  The important idea isn't "always use %". It's understanding that MariaDB permissions can depend on both username and connection origin.

9. Port 3306
  MariaDB normally listens on: 3306

  That's why your log says:
    port: 3306

  Eventually:
    wordpress container
          │
          │ TCP :3306
          ▼
    mariadb container

  But this does not mean you need to expose 3306 to your computer or the internet.

  That's a huge Docker distinction:
    INTERNAL DOCKER NETWORK

    wordpress ─────3306─────► mariadb

  For Inception, the public entry point is NGINX on port 443


10. Why did we use 0.0.0.0?
  Originally MariaDB listened on:
  127.0.0.1

  127.0.0.1 means loopback, essentially:
    MariaDB container
    ┌─────────────────────┐
    │                     │
    │ MariaDB ◄── localhost
    │                     │
    └─────────────────────┘

  WordPress container ❌

  So you configured:
    [mysqld]
    bind-address = 0.0.0.0

  Now MariaDB listens on all network interfaces available inside its container:
    WordPress
        │
        │ Docker network
        ▼
    MariaDB :3306

  That's why your successful log changed to:
    Server socket created on IP: '0.0.0.0', port: '3306'.


11. What is /var/lib/mysql?
  This is one of the most important directories in your project.

  MariaDB stores its database files under:
    /var/lib/mysql

  Conceptually:
    /var/lib/mysql/
        │
        ├── system database stuff
        │
        └── WordPress database data

  Here's the Docker problem.
    Containers are disposable.
    container
      ↓
    deleted 💀
      ↓
    container filesystem disappears

  You definitely don't want:
    docker compose down

          ↓

    goodbye WordPress database 👋

  That's why we'll eventually attach a Docker named volume to:
    /var/lib/mysql

  The subject requires persistent volumes for MariaDB and WordPress data.

  Then:
    MariaDB container
          │
          │ /var/lib/mysql
          ▼
    Docker Volume
          │
          ▼
    persistent data

    Container dies?
    💀 container
        │
        X
    💾 volume survives

  New container attaches to the same volume and gets the database back.

12. Why mariadb-install-db?
  A brand-new MariaDB data directory can't simply magically become a working database.
  It needs initial system tables and internal structures.

  That's what:
    mariadb-install-db

  does.

  Very simplified:
    empty /var/lib/mysql
            │
            ▼
    mariadb-install-db
            │
            ▼
    initialized MariaDB data directory
            │
            ▼
    mariadbd

  And that's why your script checks:
    if [ ! -d "/var/lib/mysql/mysql" ]; then

  We're asking:
    Has MariaDB already been initialized?

  If no:
    initialize it

  If yes:
    don't destroy/reinitialize existing data

  This becomes much more meaningful once /var/lib/mysql is backed by the persistent volume.

13. What's /run/mysqld/mysqld.sock?
    You encountered this error earlier.

    MariaDB can communicate through both:
      TCP/IP
        → port 3306

    Unix socket
      → /run/mysqld/mysqld.sock

    A Unix socket is a local communication mechanism between processes on the same Linux system.

    MariaDB wanted:
      /run/mysqld/mysqld.sock

    but the directory didn't exist.

    So you created it:
      mkdir -p /run/mysqld

    and then:
      chown mysql:mysql /run/mysqld

    Meaning:
      create directory
            +
      give mysql permission to use it

      That's why the original socket error disappeared.

14. Why USER mysql?
  Your first MariaDB attempt gave:
    Please consult the Knowledge Base to find out
    how to run mysqld as root!

  Docker normally starts as:
    root

  But a database server doesn't need to run with unrestricted root privileges.

  So:
    USER mysql

  means subsequent container execution happens as the mysql Linux user.

  Important distinction again:
    Linux user:       mysql
    MariaDB user:     wpuser
    WordPress user:   nchairun

  These are three completely different kinds of user accounts.
  That one is worth remembering for evaluation.


15. Why exec mariadbd?
  Your script ends with:
    exec mariadbd

  Without exec, conceptually you could have:
    PID 1 → init.sh
              │
              └── mariadbd

  With:
    exec mariadbd

  the shell is replaced:
    PID 1 → mariadbd

  That's cleaner for Docker because MariaDB becomes the container's main process and receives signals directly.
  Your subject explicitly warns that PID 1 behavior matters and that hacky commands for keeping containers alive aren't allowed.
