1. THE BIG PICTURE
------------------
Browser -> HTTPS :443 -> NGINX -> WordPress/PHP-FPM -> MariaDB :3306
                                                       |

                                                       |
                                                       v

- NGINX receives HTTPS requests.
- WordPress runs the website and needs to save/retrieve data.
- WordPress sends SQL queries to MariaDB.
- MariaDB stores and retrieves structured data.
- MariaDB is reachable by WordPress over the internal Docker network.
- NGINX is the only public entry point for Inception (port 443).

Remember:
  Database = organized, persistent data
  SQL      = language for working with relational data
  MariaDB  = database management software
  Docker   = environment in which the software runs

2. DATABASES, TABLES, AND RELATIONSHIPS
---------------------------------------
A database is an organized collection of data. MariaDB can manage multiple
separate databases. Each database contains tables made of rows and columns.

Example:
  users
    id | username | email
     1 | alice    | alice@example.com
     2 | bob      | bob@example.com

  posts
    id | author_id | title
     1 | 1         | Hello World
     2 | 2         | My First Blog

The posts.author_id value can refer to users.id. This is the idea behind
relational data. A formal foreign-key constraint can enforce a relationship,
but the example alone does not create one.

WordPress creates its own tables during installation, typically including:
  wp_users, wp_posts, wp_comments, wp_options
(The prefix can be configured.)

3. SQL BASICS
-------------
SQL = Structured Query Language. It is a language, not a server program.

Useful commands:
  CREATE DATABASE  Create a database
  CREATE TABLE     Create a table
  INSERT INTO      Add rows
  SELECT           Read rows
  UPDATE           Modify rows
  DELETE           Delete rows
  GRANT            Give database permissions

Example SQL session (practice in a separate database):

  CREATE DATABASE playground;
  USE playground;

  CREATE TABLE students (
      id INT AUTO_INCREMENT PRIMARY KEY,
      name VARCHAR(50) NOT NULL,
      campus VARCHAR(50),
      level INT
  );

  INSERT INTO students (name, campus, level)
  VALUES ('Alice', 'Berlin', 5), ('Bob', 'Frankfurt', 8);

  SELECT * FROM students;
  SELECT name FROM students WHERE campus = 'Frankfurt';
  SELECT * FROM students ORDER BY level DESC;
  SELECT COUNT(*) FROM students;

  UPDATE students SET level = 9 WHERE name = 'Bob';
  DELETE FROM students WHERE name = 'Alice';

IMPORTANT: UPDATE or DELETE without WHERE can affect every row.
To remove the entire practice database, if no longer needed:
  DROP DATABASE playground;
Never experiment with destructive queries on your real WordPress database.

4. MARIADB VS MYSQL
-------------------
- MySQL and MariaDB are relational database management systems (RDBMS).
- MariaDB originated as a fork of MySQL in 2009.
- They share much SQL syntax and many historical names/conventions.
- In Inception, you use MariaDB; you do not need a separate MySQL server.
- The internal database named 'mysql' is part of MariaDB; it does NOT mean
  that a separate MySQL server is installed.

5. SERVER VS CLIENT
-------------------
  mariadbd = running MariaDB SERVER process
  mariadb  = command-line CLIENT used to connect and execute SQL

  mariadb client -- SQL --> mariadbd server --> database files

The server normally listens on TCP port 3306 for network connections.
Local clients can also connect through a Unix socket, commonly:
  /run/mysqld/mysqld.sock

A Unix socket allows processes on the same system/container to communicate
without using a TCP network connection.

7. THREE DIFFERENT KINDS OF USERS
---------------------------------
Linux user:
  mysql       Runs the MariaDB server process with limited OS privileges.
  root        Linux administrator inside the container.

MariaDB account:
  wpuser      Used by WordPress to authenticate to the database.
  root        Database administrator account.

WordPress website users:
  siteowner   Website administrator.
  writer      Regular website user.

These are separate account systems. A MariaDB user is NOT a WordPress user.

Example account setup (illustrative, not a command to rerun blindly):
  CREATE USER IF NOT EXISTS 'wpuser'@'%' IDENTIFIED BY 'password';
  GRANT ALL PRIVILEGES ON wordpress.* TO 'wpuser'@'%';

  wordpress.*   = all tables in the wordpress database
  'wpuser'@'%'   = MariaDB account wpuser, with % as a host wildcard

WordPress should have permissions for its own database, not every database
on the MariaDB server.

8. DOCKER COMPOSE AND THE CONTAINER SHELL
----------------------------------------
Run these commands on your HOST (where docker compose is available):

  docker compose ps
  docker compose exec mariadb whoami
  docker compose exec -u root mariadb sh
  docker compose exec -u root mariadb mariadb -u root

Breakdown of the last command:
  docker compose exec = execute inside an already-running service container
  -u root             = run process as the Linux root user
  mariadb             = Compose service name
  mariadb             = MariaDB client executable
  -u root             = connect as MariaDB database user root

The two 'root' values refer to different account systems.

Prompt guide:
  3-B-9%                Host zsh shell
  #                     Container shell (sh, running as root)
  MariaDB [(none)]>     MariaDB SQL client; no database selected
  MariaDB [wordpress]> MariaDB SQL client; wordpress selected

Inside the container shell (#), use:
  whoami
  ls /var/lib/mysql
  ps aux
  mariadb -u root

Do NOT run 'docker compose ...' inside the container: Docker CLI is not
installed there. Use 'exit' to return to the host shell.

Your root database login worked because MariaDB root uses local Unix-socket
authentication in your setup, which checks the connecting Linux identity.

9. MARIADB SQL PROMPT TIPS
--------------------------
  MariaDB [(none)]>  Ready for a new SQL statement
  ->                  Statement is unfinished; MariaDB awaits more input
  ;                   End and execute a SQL statement
  \c                  Cancel an unfinished statement
  EXIT;               Leave the SQL client

Correct:
  SHOW DATABASES;

Incorrect:
  SHOW DATABASE;

If you type 'SHOW DATABASE' without ';', the next line is appended to the
same statement. Use \c to cancel before trying again.

10. DOCKER NETWORKING
---------------------
  WordPress container --- TCP :3306 ---> MariaDB container

MariaDB can be configured with:
  [mysqld]
  bind-address = 0.0.0.0

  127.0.0.1 = listen only on loopback inside the MariaDB container
  0.0.0.0   = listen on all available container network interfaces

WordPress is in a DIFFERENT container, so loopback-only binding would block
its direct network connection. The Docker network allows communication
without publishing MariaDB port 3306 to the host or internet.

11. PERSISTENCE: /var/lib/mysql AND THE DOCKER VOLUME
-----------------------------------------------------
MariaDB stores database files under:
  /var/lib/mysql

You observed directories/files such as:
  wordpress/          Application database files
  mysql/              Internal MariaDB system data
  ibdata1             InnoDB system tablespace
  ib_logfile0         InnoDB redo log file

Compose volume mapping:
  volumes:
    - mariadb_data:/var/lib/mysql

The named volume persists independently of the container's writable layer.
A recreated container can reuse the same volume and retain database data.
Do not manually edit or delete live MariaDB data files.

NOTE: 'docker compose down' normally retains named volumes.
'docker compose down -v' removes Compose-managed named volumes and can
therefore destroy your database data. Be careful with -v.

12. INITIALIZATION AND THE ENTRYPOINT
-------------------------------------
A new MariaDB data directory needs initial system tables:
  mariadb-install-db

Your entrypoint checks whether initialization has already happened:
  if [ ! -d "/var/lib/mysql/mysql" ]; then
      # initialize MariaDB and create the application database/account
  fi

Simplified startup:

  Container starts
         |
         v
  Does /var/lib/mysql/mysql exist?
         |
       NO / YES
       /     \
      v       v
  Initialize  Reuse existing data
      \       /
       v     v
   exec mariadbd --user=mysql
         |
         v
   MariaDB server is PID 1

On initial setup, your script temporarily starts MariaDB to execute SQL,
creates the wordpress database and wpuser permissions, stops that temporary
server, and finally starts the long-running server.

The directory /run/mysqld must exist and be writable by the mysql Linux
user for the local socket. Your setup used:
  mkdir -p /run/mysqld
  chown mysql:mysql /run/mysqld

13. WHY USER mysql AND exec MATTER
----------------------------------
Dockerfile USER mysql:
  Runs the container's processes as the less-privileged Linux mysql user,
  rather than running the database server as Linux root.

Entry point:
  exec mariadbd --user=mysql

'exec' replaces the entrypoint shell with the MariaDB server process.
This makes mariadbd PID 1, the container's main process, so it receives
Docker's stop signals directly.

Your 'ps aux' showed:
  USER    PID   COMMAND
  mysql     1   mariadbd
  root     74   sh
  root     82   ps aux

The shell and 'ps' were extra processes created during your inspection.

14. SECRETS AND CONFIGURATION
-----------------------------
Your Compose setup provides configuration via .env and a database-password
secret. Inside the MariaDB container, Docker mounts that secret at:
  /run/secrets/db_password

The entrypoint reads it with:
  DB_PASSWORD=$(cat /run/secrets/db_password)

Your chosen variable names include:
  MARIADB_DATABASE=wordpress
  MARIADB_USER=wpuser

Keep passwords out of committed source files. Do not print secrets in logs.

1. What does .cnf mean?
  .cnf stands for configuration.
  It's a text file containing settings that MariaDB reads when starting.

  For example:
    [mysqld]
    bind-address = 0.0.0.0
    port = 3306

  - [mysqld] identifies a configuration section for the database server.
  - bind-address = 0.0.0.0 tells MariaDB to listen on all available network interfaces.
  - port = 3306 specifies the TCP port MariaDB listens on.

WordPress container
        |
        | TCP connection, port 3306
        v
MariaDB container
        |
        v
MariaDB server (mariadbd)

By default, MariaDB on Debian may be configured to listen only on:
  bind-address = 127.0.0.1

That means MariaDB accepts TCP connections only from inside its own container.
But WordPress is running in a different container.

Inception configuration use
  bind-address = 0.0.0.0

SQL is the language you use to talk to MariaDB.

Think:
    MariaDB = database server
    SQL     = language you speak to it

The commands you need:
    -- See all databases
    SHOW DATABASES;

    -- Create a database
    CREATE DATABASE wordpress;

    -- Safer version
    CREATE DATABASE IF NOT EXISTS wordpress;

    -- Create a database user
    CREATE USER 'wpuser'@'%' IDENTIFIED BY 'password';

    -- Give wpuser access to the wordpress database
    GRANT ALL PRIVILEGES ON wordpress.* TO 'wpuser'@'%';

    -- Reload permission information
    FLUSH PRIVILEGES;

    -- Read/query information
    SELECT User, Host FROM mysql.user;

---

How to read SQL

This:
    CREATE USER 'wpuser'@'%' IDENTIFIED BY 'password';

means:
    CREATE USER
        ↓
    wpuser
        ↓
    from % (other hosts/containers)
        ↓
    with this password


This:
    GRANT ALL PRIVILEGES ON wordpress.* TO 'wpuser'@'%';

means:
    GRANT ALL PRIVILEGES
            ↓
    on wordpress.*
    ↓         ↓
    database   everything inside it
            ↓
    to wpuser

The 6 words to remember

CREATE  → make something
SHOW    → show things
SELECT  → read/query something
GRANT   → give permission
DROP    → delete something ⚠️
FLUSH   → reload privilege information
