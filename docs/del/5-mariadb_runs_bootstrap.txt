Why start it twice?
    The first start is temporary, just so our initialization script can talk to the database and configure it.

The second:
    exec mariadbd

    is the real long-running server that keeps the container alive and becomes PID 1, 
    which is important for proper container behavior and something your subject explicitly tells you to understand.

So the mental model is:
    temporary server → configure database 🔧
    final server      → actually run database 🚀

--bootstrap

    Normally:
        mariadbd

    means:
        Start MariaDB as a normal server and keep running.

    But:
        mariadbd --bootstrap

    means:
        Start MariaDB temporarily in setup/initialization mode, execute SQL directly, then finish.

    That's why we can do:
        mariadbd --user=mysql --bootstrap <<EOF
        CREATE DATABASE wordpress;
        CREATE USER ...;
        GRANT ...;
        EOF

    Flow:
        --bootstrap
            ↓
        MariaDB setup mode
            ↓
        execute CREATE DATABASE
        execute CREATE USER
        execute GRANT
            ↓
        finish

    Then afterward:
        exec mariadbd

    starts the real MariaDB server that stays running as PID 1.
    So remember:
        --bootstrap  = configure MariaDB 🔧
        mariadbd     = run MariaDB normally 🚀

    And <<EOF ... EOF is simply how our shell feeds those SQL commands into bootstrap mode.
